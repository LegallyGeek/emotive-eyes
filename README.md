# emotive-eyes

Procedural, spring-animated robot eyes for reporting the status of app inputs, in the spirit of
Cozmo's expressive eyes. One shared spec drives two implementations:

- **Web:** a pure-JavaScript core plus a Svelte 5 component ([`js/`](js/README.md)), with a demo
  app ([`web-demo/`](web-demo/README.md)).
- **Android:** a Kotlin core plus a Jetpack Compose renderer and a demo app
  ([`android/`](android/README.md)).

Each eye is a rounded rectangle with eyelids cut out of it, described by nine numbers. Expressions
(32 presets) are values for those numbers, transitions are springs, and blinks (two styles:
`narrow`, the default, where each eye closes to its own line, and `wide`, where the eyes merge into
one line), idle glances and status glances
are layered on top. Defaults suit the Light Phone III target: white eyes on black, glow off.

## Layout

| Path            | What                                                                                   |
| --------------- | -------------------------------------------------------------------------------------- |
| `spec/`         | `SPEC.md` (normative contract), `runtime/*.json` (expressions, motion, status mapping) |
| `spec/vectors/` | test vectors generated by the JS reference; the Kotlin tests must match them to 1e-9   |
| `js/`           | npm package `emotive-eyes` (core) and `emotive-eyes/svelte` (component)                |
| `web-demo/`     | Vite + Svelte demo: expressions, live tuning, simulated inputs, motion controls        |
| `android/`      | Gradle project: `emotive-eyes-core` (JVM), `emotive-eyes-compose`, `demo`              |

Both platforms follow Clean Architecture layers (`entities`, `features`, `interfaces`, `drivers`)
with imports pointing inward only.

## Quick start

Web (Node 22+):

```sh
npm install
npm run dev        # demo at http://localhost:5173
npm run lint && npm run format:check && npm test && npm run check && npm run build
```

Android (JDK 17, Android SDK 36):

```sh
cd android
./gradlew ktlintCheck lint :emotive-eyes-core:test :demo:assembleDebug
./gradlew :demo:installDebug
```

## Changing expressions or motion

Edit `spec/runtime/*.json` (the web demo's **Tune** tab produces paste-ready expression JSON),
then run `npm run vectors` to regenerate `spec/vectors/` and re-run both test suites. Never edit
the vectors by hand.

## Reduced motion

Both platforms honour the system preference (`prefers-reduced-motion` on the web; Android's
"Remove animations", i.e. `animator_duration_scale = 0`). In that mode transitions and glances are
critically damped (no bounce) and the random idle gaze is off; blinks remain. Glances stay on
because they show which input changed. Many emulators and some devices ship with animations
removed, so check `adb shell settings get global animator_duration_scale` if the eyes look calmer
than expected. The Android demo shows whether it is following the system and lets you override
it; the web demo's Motion tab can force reduced motion on.
